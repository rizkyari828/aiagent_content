- Basic Storyboard: DONE. `GenerateStoryboard` reuses the existing durable job type with no schema/migration change. The canonical input is the `Approved` `ReviewedScript` (`reviewed_scripts` row), read directly and never from a historical GenerateScript `Job.Result`. Missing project, missing reviewed script, and draft/unapproved script are rejected at enqueue and in the handler (`content_project_not_found`, `storyboard_script_not_found`, `storyboard_script_not_approved`). Result is an immutable structured `Job.Result` (`title`, ordered `scenes[]` of `heading` + `visual`) exposed through the existing `GET /api/jobs/{jobId}`.
- Basic Asset Collection: DONE. Manual registration associates a local file under an approved `Assets:RootPath` with one storyboard scene, using the completed immutable GenerateStoryboard `Job.Result` as input; no external providers or generation. New additive `scene_assets` table/migration `20260918041620_AddSceneAssets` stores only canonical metadata (project, source job, scene index, type, relative path, byte size, SHA-256 content hash, origin, source/creator/license/retrievedAt, createdAt) and never file bytes. One asset per project scene (unique index); external assets require source and license. Path handling rejects rooted/absolute paths, `.`/`..` segments, Windows drive prefixes, and any path that traverses a symbolic link, and every candidate must resolve inside the configured root. Missing project/job/scene/file, duplicate scene, invalid hash, and missing provenance are rejected with stable codes.

Registration is gated on an existing project and a completed GenerateStoryboard `Job.Result`, then reuses the existing `IAssetFileStore` for approved-root path safety and integrity hashing. Duplicate narration, missing/invalid storyboard, missing file, root escape, and missing external provenance are rejected with stable codes.
